# Changelog

## Unreleased

- **Audit repositories:** `bin/audit new <dir>` creates a repository for one audit from `template/`: the framework pinned as the `harness/` submodule, the code under audit in `audit.json` as targets pinned to full commits (a submodule, an ignored clone, or an existing checkout at a path), one engagement per audited Foundry project, the workspace beside them, and an `AGENTS.md`, `.mcp.json` and Claude Code settings for agent work. In the audit repository, `bin/audit setup` reconciles the checkouts and the workspace with `audit.json` idempotently (including the first snapshot of each engagement), `target pin` moves a pin, `snapshot` registers new snapshots and refuses code that is not the pinned code unless `--allow-dirty`, `status` checks everything read-only with a fix per failure, and `hook` prints the capture hook for user settings, guarded so that it records only Claude Code sessions started in the audit repository. Harness writes go through the harness CLI. See [docs/audit-repo.md](docs/audit-repo.md).
- **Agent-mediated decisions (operator decision 2026-10-14):** `harness mcp` is an MCP server (declared in `.mcp.json` for omp and Claude Code) whose tools `harness_overview`, `harness_present`, `harness_decide`, `harness_request_check`, `harness_records`, `harness_call`, `harness_run_jobs` and `harness_capture` let an agent present pending decisions to the auditor, discuss them and record them through an agent session. The requirement that a decision is the auditor's sole choice is lifted and nothing binds the human's participation; provenance is labelled instead: the principal `agent-session`, display receipts naming the agent client, the rationale authorship the agent reports, the capture channel `agent-session-relay` for relayed input, and a `harness status` line. The controller's decision rules are unchanged; the interactive screen and the unattended approver stay available. See [docs/agent-review.md](docs/agent-review.md).
- **Unattended approval (operator opt-in, off by default):** `harness unattended enable|disable|status` delegates `accept_scope_and_policy` and `authorize_work` per engagement to an approver that applies a complete draft as written; its decisions carry the principal `unattended-approver` and the authorship `agent_unattended`, and `harness status` lists them. `record_flow_review` is delegable only when named in `--kinds`: it lifts the batch gate without marking functions reviewed, adds a gap saying no human reviewed the flow, is labelled in the report and keeps closure incomplete until a flow review on the screen or through an agent session. See [docs/operator-choices.md](docs/operator-choices.md).
- **Yolo loop (operator request 2026-10-14, opt-in):** `harness yolo run -e E --charter F` runs an agentic, unattended discovery -> test -> report loop, for example overnight. A deterministic governor sequences sandboxed role agents (comprehension, planner, investigator, challenger) and tool jobs, admits each cycle's batch through the unattended approver within the operator's charter (nothing defaulted), requests a clean replay of a demonstrated violation, and has the investigator submit the review packet. It records no disposition: candidate findings wait for the auditor. Runs are `yolo_run` records with a controller-rendered report (`harness yolo status|report|stop`, MCP tool `harness_yolo_report`, a `harness status` line). The governor acts as the principal `yolo-governor` on the controller channel, limited to requesting work and recording its run; `prepare_work` is now open to the controller channel. A run ends at its cycle limit or deadline, at review capacity, when nothing can be admitted, on budget or discovery exhaustion, on `yolo stop` or a pause, or after the charter's number of consecutive failed rounds. See [docs/cli.md](docs/cli.md#7-yolo-runs-unattended-discovery-test-and-report-operator-opt-in) and [docs/operator-choices.md](docs/operator-choices.md).
- **Yolo loop on a real target:** the charter requires `agents.max_tokens` (output per model turn; an investigator writes a PoC fixture in one tool call) and `agents.call_timeout_seconds` (the run's provider-call limit, in place of the proposed 120 s, which a long fixture can outlast). Agents get the policy scope's sources when the policy names paths from the repository root and the snapshot was registered from a subdirectory (before, they got every non-excluded Solidity file in path order, which put dependencies ahead of the scope). The reference investigator's `request_experiment` selects tests with forge's match flags and declares an expectation per selected test, so attack tests and their controls run in one experiment. A fixture that fails to build (a compiler error, or forge refusing incompatible pinned compiler versions) returns the diagnostics (up to 4,000 characters) in its result. A proposal based on an investigation or scenario-variant revision followed only by job dispatch is applied to the current revision: a challenger's prerequisite review and an investigator's variant outcome no longer conflict with the job links `request_job` adds after the round's context was built.
- **Agent contexts carry execution results:** an agent context about an investigation now includes the trusted runner's evidence from its experiment, replay and control jobs. Before, agents saw only the job links on their variants, so a later investigator round could not repair a failing fixture or record a variant's outcome from evidence, and a challenger could not check what the tests asserted.
- **Charter guidance:** the yolo charter requires `discovery.focus` (the operator's direction for comprehension and planning rounds), `agents.notes` (appended to every agent task) and `agents.reference_paths` (snapshot paths, such as test deployment helpers, that every agent context carries after the policy scope); each may be empty, and each job records the task it ran with.
- **Agent references and batch selection:** the reference agents' tools turn a bare record id or `id@revision` into an exact reference at the revision the agent's context holds, and refuse at once a record outside it. Agents name records that way, and before, the controller refused those proposals as `record undefined@undefined not found` (a store lookup now names a malformed reference instead). When the planner's batch cannot be used, the governor takes the questions that planner round proposed first, and ranks questions an agent or the auditor proposed ahead of the lead generators' heuristic leads.
- **Snapshots:** an upstream dependency root under a git-ignored directory (for example `node_modules/@celo/contracts`) is frozen and verified instead of being dropped.
- **Foundry:** builds run with `FOUNDRY_LINT_LINT_ON_BUILD=false`; forge 1.7.0's linter failed a build the compiler accepts.

## 0.1.0 — 2026-10-14

First release: the walking skeleton of the human-led EVM audit harness (design: `../framework-design-lab/`, DEC-008, Q-020). Contract version 1 ([docs/contracts.md](docs/contracts.md)).

### Included

- **Core:** one local controller that runs jobs one at a time as child processes it owns; append-only Git-backed engagement store and hash-pinned evidence archive; record contracts as JSON Schemas; every write is an atomic controller operation. Worker grants are bound to their engagement and re-validated at commit; crash recovery and stale-lock reclaim.
- **Decisions:** proposals, captured input and batched confirmation, clarification queue, batch authorization with flow review, review packets with bound positions and derived challenge independence, impact-scaled dispositions with claim-bound positive controls, premise revision, comprehension records, method versions and metrics.
- **Execution:** trusted runner and receipt collector; bubblewrap sandbox with no network; Foundry adapters, including property campaigns with adequacy from a reviewed fault; per-attempt provider broker socket with content validation, ceiling reservations and `outcome_unknown` accounting; reference role agents; conformance checks.
- **Change handling:** frozen snapshots, deterministic inventory from compiler artifacts, snapshot diffs, dependency probes and freshness tiers, automatic reruns, fix assessment, intake scan for steering and deceptive characters.
- **Reporting and method:** controller-computed required set, reports, export and quarantined import, closure, mechanism library and lessons, context builder, evaluation contracts, canaries, held-out comparisons, control checks, scheduling across batches, lead generators.
- **Interface:** trusted decision screen with display receipts, capture channel (terminal wrapper and Claude Code `UserPromptSubmit` hook), `harness` CLI.
- **Providers:** omp credential gateway as the provider broker's upstream (`omp-anthropic`, `omp-openai-codex`; omp version pinned, 80% plan headroom, notional spend). A 5xx relayed by the gateway is `outcome_unknown` with the reservation held; a 4xx stays a definite refusal.
- **Agent host:** reference host passes every conformance check; Claude Code passes all five agent-tool conditions in terminal-wrapper mode ([trial](docs/agent-host-trial.md)).

### Operator decisions recorded

- Sandbox: bubblewrap (2026-10-13).
- Model provider: omp's credential gateway (2026-10-13), with the terms and billing caveats in [docs/operator-choices.md](docs/operator-choices.md).
